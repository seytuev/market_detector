# Отчёт: синхронизация свечей

Дата: 12.10.2026.
Основание: [ТЗ](Candle_Synchronization_Spec_RU_2026_10_12.md).

## Реализованное поведение

- Общая кнопка «Обновить данные» на рабочем экране и LTF. Она загружает свечи и котировки с источников для всех включённых основных инструментов, а затем обновляет экран.
- Одно фоновое задание с сохранением ID, прогресса, результатов и ошибок в БД. Повторные старты возвращают активное задание; после завершения действует пауза 15 секунд.
- Синхронизация H1 и настроенных HTF D1/W1: сверка двух закрытых баров, заполнение пропусков последних 200 закрытых баров, догрузка хвоста, текущая свеча, обработка ревизий штатными движками.
- HTF-контекст в ручном проходе обновляется перед H1. Закрытия проходят по времени; обычное обновление не запускает полный replay. Первичная загрузка и восстановление внутреннего пропуска используют существующий механизм исторического восстановления.
- Общая координация фоновых и ручных операций: владение инструментом, последовательное выполнение вычислений общего движка H1, максимум два одновременных запроса на биржу.
- Учитывается `Retry-After`, включая дату HTTP. Повтор сетевого запроса ограничен; новые обращения к той же бирже соблюдают установленную паузу.
- Первый запрос на границе H1/D1/W1 — через 5 секунд; при отсутствии ожидаемого закрытия/текущей свечи — повторные попытки через 15, 30 и 60 секунд. Периодический опрос сохраняется.
- Границы периодов вычисляются по времени открытия полученных свечей источника; для начального запроса используется календарь UTC с понедельником для W1.
- Основной экран и LTF перечитывают снимок после reconnect. Возврат во вкладку и восстановление сети инициируют сверку при возрасте чтения более 15 секунд. Видимая страница резервно перечитывает данные раз в 30 секунд, независимо от формального состояния WebSocket.
- Сохраняются масштаб, просмотр прошлого и следование за последним баром. Поздний ответ для другого инструмента/таймфрейма не применяется. Свечи могут возвращаться с версией состояния; связанные снимки проверяются и перечитываются при расхождении.
- Отдельная панель свежести показывает результат задания, время синхронизации и состояние каждого канала. Соединение WS и актуальность данных различаются.
- При восстановлении свежесть обновляется до доставки событий: успешное восстановление не оставляет новые события заблокированными старым флагом ошибки. Дедупликация и правила исторических/отложенных уведомлений сохранены.
- После получения владения расчётом прерванное задание помечается ошибкой перезапуска. При остановке процесса фоновое задание завершается до закрытия БД.
- Предел задания — 10 минут. Если вычислительный поток продолжает работу после предела, это явно показано; владение удерживается до фактического завершения, конфликтующий повтор не допускается.

Дневной модуль альткоинов остаётся отдельным заданием и не включён в общую кнопку согласно области ТЗ.

## API и точки подключения

| Место | Назначение |
|---|---|
| `app/services/data_sync.py` | Координатор, состояние каналов, задания и планировщик границ |
| `app/worker.py` | Общая обработка загруженных свечей, сериализация вычислений, существующая доставка |
| `app/main.py` | Подключение координатора к API и остановка задания перед закрытием БД |
| `app/web/data_sync_api.py` | Авторизованные POST `/api/data-sync`, GET `/api/data-sync/status`, GET `/api/data-sync/{job_id}` |
| `app/web/api.py` | Совместимый режим `/api/candles?...&with_version=true`; прежний формат списка остаётся по умолчанию |
| `app/web/static/data_sync.js` | Кнопка, прогресс, свежесть, объединение чтений и восстановление вкладки |
| `app/web/static/common.js` | Актуальное состояние заменяемого WebSocket и сохранение диапазона графика |
| `app/services/quality.py` | Ожидаемое закрытие, отсутствие текущего бара и ошибки обработки в общей оценке качества |

Для использования нужен обычный запуск приложения вместе с воркером (`python -m app.main`). Отдельно запущенный API без исполнителя возвращает 503 на запуск синхронизации и показывает недоступность обновления. Изменения серверного кода вступают в силу после перезапуска процесса.

Отдельная LTF-страница обычно перенаправляет на рабочий экран; собственный интерфейс совместимости проверен с параметром `stay=1`.

## Проверки

### Автоматические сценарии

`tests/test_data_sync.py` содержит 21 сценарий с реальными движками и управляемыми ответами источника/временем:

- Ручная догрузка всех каналов и повторное выполнение без новых фактов.
- Доставка живого касания зоны и отсутствие повторной доставки при следующей синхронизации.
- Частичный отказ и успешный ответ источника без ожидаемого бара.
- Заполнение внутреннего пропуска H1 позади уже обработанного курсора.
- Ревизия H1 без нового закрытия.
- Публикация бара только на третьей попытке.
- Первый запрос через 5 секунд отдельно для H1/D1/W1.
- Календарь периода по наблюдаемому смещению источника для H1/D1/W1.
- Одновременный ручной и периодический проходы.
- Превышение предела задания с удержанием владения до завершения потока.
- Восстановление статуса после перезапуска.
- Авторизация, доступность исполнителя, API задания, cooldown и версия свечей.
- Исключение выключенных инструментов.
- Ошибка вычисления после сохранения свечей и успешная повторная обработка без пропуска закрытий.
- Соблюдение `Retry-After` и ограничение числа попыток.
- Обновление свежести перед доставкой.
- Остановка фонового задания и снятие признака незавершённой обработки.

Также проверены существующие тесты воркера, LTF, котировок, ревизий, версий состояния, API, качества, графиков и адаптеров. Полные общие прогоны в одном процессе прерывались; связанные с изменением проверки и остальные группы запускались отдельно. Полный единый прогон не заявляется как успешно завершённый.

### Браузерная приёмка

`tests/data_sync_browser_server.py` запускает изолированное приложение с БД в памяти и тестовым источником; рабочая БД и внешние биржи не используются.

`tests/data_sync_browser_check.js` проверяет в Chrome:

1. Ручное обновление и итог задания в двух окнах.
2. Догрузку свечей и сохранение выбранного диапазона на основном экране и LTF.
3. Изменение OHLC во время разрыва соединения и восстановление после reconnect.
4. Возврат из скрытой вкладки.
5. Резервное чтение при подключённом WS без новых сообщений.
6. Объединение одновременных запросов снимка.
7. Игнорирование задержанного ответа для ранее выбранного актива.
8. Мобильную вёрстку шириной 390 px без горизонтального переполнения.

Браузерная приёмка пройдена. Скриншоты мобильных экранов визуально проверены. Проверка синтаксиса изменённого JavaScript и `git diff --check` выполнены.

## Пределы подтверждения

Задержки и ошибки воспроизведены управляемым источником. Фактическая задержка публикации у бирж в рабочем окружении этим не измеряется; для неё добавлены время запроса/обработки, диапазон, количество новых/исправленных баров, курсоры и причины отказов в диагностике.

Изменения подготовлены в рабочем каталоге. Развёртывание и перезапуск рабочего сервиса в рамках реализации не выполнялись.
