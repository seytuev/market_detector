# Доставка в темы Telegram

Для группы Market Researcher STV с темами используется `TELEGRAM_CHAT_ID=-1004352888499`.
Старый ID обычной группы `-5311567627` для новой доставки больше не подходит.

| Переменная | Значение | Содержимое |
|---|---|---|
| `TELEGRAM_TRADING_THREAD_ID` | `2` | HTF, LTF/H1, контекст рынка |
| `TELEGRAM_SCREENER_THREAD_ID` | `3` | Скринер альткоинов D1/W1 |
| `TELEGRAM_X_FEED_THREAD_ID` | `4` | Важные публикации X после разбора |
| `TELEGRAM_TG_FEED_THREAD_ID` | `6` | Важные публикации Telegram после разбора |

Служебные сообщения и напоминания о катализаторах без отдельного адреса темы
остаются в General. Пустой ID темы сохраняет обычную отправку без темы.
Боту нужен доступ к группе и право отправлять сообщения/фотографии.

Рассылка лент включается через `RESEARCH_FEED_NOTIFICATIONS_ENABLED=1`.
Фильтр: успешный разбор текущей редакции, значимость минимум 4/5
(`RESEARCH_FEED_NOTIFICATION_MIN_IMPACT=4`, допустимо повысить до 5),
уверенность medium/high. Оценку значимости делает модель отдельно от
направления и уверенности. Это оценка новости, а не рекомендация сделки.
Нейтральная важная новость тоже может пройти фильтр.

Для Telegram используется полный разбор, а при его отсутствии — классификация
ленты; для X — классификация. Новый запрос классификации X включает значимость
в тот же вызов модели, без дополнительного платного запроса. Старые результаты
без оценки значимости не переанализируются только ради рассылки.

Граница включения сохраняется по группе, теме и источнику. Материалы,
сохранённые или опубликованные раньше неё, не рассылаются при включении.
Повторный запуск не меняет границу и не создаёт дубли одной редакции.
Перед отправкой проверяются удаление, смена редакции и выключение рассылки.

Тема сохраняется вместе с пакетом outbox. Повторная попытка, обновление карточки
и поздняя доставка графика используют исходную тему. Тихие сводки формируются
отдельно для каждой темы; HTF/LTF объединяются, поскольку их тема общая.
Панели «Подробнее» и текущие графики кешируются с учётом темы.

Настройки задаются в окружении работающего сервиса Railway; локальный `.env`
используется только при запуске из рабочей копии. После изменения кода и
переменных требуется обновить процесс и проверить `/api/live`, `/api/ready`
и журнал ошибок доставки. Изменений схемы БД для маршрутизации нет.

## Исправление повторного попадания в General, 17.10.2026

Настройки тем в Railway сохранились, но последующие автоматические деплои
из `main` заменили разовую локальную сборку кодом без маршрутизации. Код,
тесты и этот документ должны входить в основную ветку репозитория;
разовая загрузка через `railway up` не заменяет сохранение исходников.

Ожидающие отправки пакеты без `message_thread_id` или с `null` получают
настроенную тему своего канала. Старые несмешанные сводки получают общую
тему участников; смешанные сводки, ещё не отправленные, разбираются
и формируются заново отдельно по темам. Доставленные и uncertain-пакеты
не переотправляются. Поздний график наследует тему родительского события.

При запуске журнал показывает `Telegram topic routing`, при успешной
отправке — `requested_topic` и `actual_topic` из ответа Telegram. Проверка
релиза включает соответствие коммита в Railway коммиту основной ветки.
