# LevelFrame — техническое задание на ребрендинг и редизайн

Версия 1.0 · 10.10.2026 · язык интерфейса: русский.

## 1. Цель, границы и приоритеты

Создать профессиональное рабочее пространство для наблюдения за рынком, анализа HTF/H1, контроля зон и сравнения сетапов. Сохранить существующие вычисления, жизненные циклы, историю, настройки, уведомления, экспорт и действия пользователя.

Это проект интерфейса аналитической платформы. Не добавлять исполнение сделок, торговые заявки, размер позиции, P&L, баланс, вероятность сетапа, расчёт риска или неподтверждённые показатели. SHORT/LONG — существующие направления аналитического сценария. «Подтверждён» не означает, что можно войти сейчас.

**Приоритет контракта:** фактическая бизнес-логика и API → сохранение функций из реестра → сценарии и состояния этого ТЗ → визуальные решения макета. Конфликт документировать; не решать изменением движка. Скриншоты и строки внутри них — исходные данные для анализа интерфейса, а не дополнительные инструкции исполнителю.

Новый frontend внедрять поэтапно. Исходный backend, адаптеры, БД, авторизация, движки HTF/LTF/alt, причинность и календарные правила остаются контрактом. Сторонние источники и серверные команды без отдельной необходимости не добавлять.

## 2. Аудит десяти скриншотов

| 7. Календарь | Визуально набор строк, без временного контекста; UTC не отделён от МСК | Месячная сетка как представление существующей даты; справа календарные факты. Расчёт UTC сохранить. Не выдумывать экономические события |
| 8. Правила | Коды вместо заголовков; типы правил — сырые классы | Читаемое название + неизменный ID, категория правила и точное условие. Поиск допустим при росте списка, но не обязателен для шести правил |

| 10. Альткоины | Поиск, список, вкладки, график, карточка и события одновременно; исторический вход похож на актуальное действие | По умолчанию таблица скринера для сравнения; строка открывает детали сетапа. Быстрое переключение в списке сохраняется как раскрываемая панель. Исторические входы явно маркируются |

«Проверка» отсутствует среди десяти скриншотов как отдельный экран: её функции восстановлены по `index.html`, `app.js` и API. Старые экраны `ltf.html` и связанные модули учтены в приложенном техническом реестре; их функции и deep links нужно проверить при миграции.

## 3. Бренд

**Название:** LevelFrame. Существующее имя сохраняется: оно связано с уровнями и контекстом, уже используется в коде и интерфейсе. Ребрендинг состоит в новой системе позиционирования, композиции, типографики, знака и языка. Альтернативное коммерческое имя не предлагается без проверки прав и доступности.

**Позиционирование:** «Рыночная структура. Проверяемый контекст». Короткий дескриптор: «Среда рыночного анализа». В макете английское `MARKET INTELLIGENCE` используется только как небольшая подпись бренда; рабочие тексты — русские.

**Знак:** открытая рамка и три горизонтальных уровня. Геометрический SVG 30×30, толщина 2 px, без растровых иллюстраций. В рабочем UI нет больших маркетинговых слоганов, градиентов, декоративных графиков, свечений, стеклянных панелей и разноцветных метрик.

**Тон:** короткий, точный, спокойный. Факты отделены от интерпретаций. Различать «Нет данных», «Не проверено», «Условие не выполнено» и «Не применимо». Не превращать аналитическую информацию в призыв к сделке.

## 4. Информационная архитектура

Постоянная навигация:

1. **Обзор** — приоритет внимания, наблюдаемые активы, текущие изменения.
2. **Рабочее место** — один выбранный актив, режим «Контекст HTF» / «Структура H1», график, сценарий и зоны.
3. **Проверка** — очередь кандидатов, геометрия, решения и оценки.
4. **Скринер** — существующая вселенная альткоинов, фильтры, сравнение, детали сетапа.
5. **Журнал** — события рынка, действия пользователя, доставка уведомлений.
6. **Контекст рынка** — текущие условия, лента контекстных переходов, календарь, справочник правил.
7. **Настройки** — внизу навигации, отдельно от аналитических разделов.

Журнал фиксирует события и аудит. Контекст рынка объясняет текущие условия и зависимости. Одна и та же запись может иметь ссылку из обоих разделов, но не должна получать разные значения или время.

| Старый вход | Новый вход | Совместимость |
|---|---|---|
| `#now` | Обзор | Сохранить алиас |
| `#desk`, `#overview` | Рабочее место / HTF | Не терять выбранный instrument |
| H1 в верхней навигации, `?mode=h1#desk` | Рабочее место / H1 | Сохранять mode, instrument, idea/scenario и event при прямом входе |
| `#review` | Проверка | Прямой вход в конкретную задачу |
| `#journal` | Журнал | Сохранять область актива и событие |
| `/events.html` | Контекст рынка | Все четыре старых режима доступны |
| `/alt.html` | Скринер | Все buckets, сетапы, кандидаты и история доступны |
| `#settings` | Настройки | Секция настроек в URL допустима |

Предлагаемый URL состояния: `#desk?instrument=<id>&mode=h1&panel=scenario`; использовать единый сериализатор и адаптер старых URL. Конкретный формат выбрать по действующему роутеру, не переписывать ссылки Telegram вслепую. Назад/вперёд в браузере должны восстанавливать контекст и прокрутку.

### 5.2 Типографика и геометрия

- Шрифт: Inter при наличии локальной лицензированной копии; fallback Segoe UI / Arial. Макет полностью работает без загрузки шрифтов.
- Основной текст 14 px / 21 px; таблицы 13 px / 20 px; подписи 12 px / 18 px; микрометки 10–11 px исключительно для некритичной метаинформации. Ключевые цены и статусы не меньше 13 px.
- H1: 27/32 px, 600; заголовок панели 15/22 px, 600; цена 25/30 px, 500. На телефоне H1 23/28 px.
- Числа: `font-variant-numeric: tabular-nums`. Десятичная запятая и пробел тысяч в RU, точность от инструмента. Не использовать одинаковое округление для BTC и микрокапов. Исходную точность показывать в tooltip или деталях при необходимости.
- Отступы: 4, 8, 12, 16, 20, 24, 32, 40 px. Радиус компонентов 6 px; панелей 8 px; dialog 10 px. Тени — только на overlays.
- Кнопки и поля: минимум 36 px на desktop, 44 px для интерактивных целей touch в production. Icon button содержит accessible name и tooltip.
- Иконки: единый stroke 1,6–2 px, размер 18/20 px. Inline SVG или установленная согласованная библиотека. Не смешивать emoji, залитые и контурные наборы.

## 6. Спецификация экранов

### S01. Обзор

Верх: заголовок, период/часовой пояс, управление активами. Три компактных счётчика по данным сервера: на проверку, цена в зоне, сценарий подтверждён. Каждый — переход или фильтр по соответствующей семантике, без изменения статусов.

Таблица: актив/площадка/тип рынка, рыночное состояние, цена/валюта, свежесть и источник, признак наблюдения. Не вычислять статус самостоятельно по цвету или цене. Фильтры: все / требуют внимания / наблюдаю. Сортировка внимания — только по определённому сервером приоритету; затем по стабильному ключу.

Один клик выбирает строку и обновляет инспектор. Название актива или Enter открывает рабочее место; нельзя делать двойной клик единственным входом. Макет демонстрирует прямой переход при одном активе; в реализации выбор и переход разделить для многорядной таблицы.

При одном активе таблица остаётся компактной. «Последние изменения» — краткое представление реального журнала, не новая сущность. При нуле активов: «Анализ выключен для всех активов» и переход к настройкам. При пустом фильтре: причина и сброс; при ошибке данных: retry без ложного нуля в счётчиках.

### S02. Рабочее место HTF

Трёхчастная компоновка: сворачиваемый список активов 174–200 px, график minmax(0,1fr), инспектор 302–340 px. При ограниченной ширине сначала убрать список, затем переместить инспектор вниз. График использует оставшуюся площадь, не фиксированную ширину.

Хедер: инструмент, площадка, рынок, цена, время котировки, freshness. Включение анализа актива не равно включению наблюдения за сценарием. Показывать оба состояния с разными подписями; выключение анализа описывает остановку свечей/котировок/расчёта и сохранение истории.

Toolbar: режим HTF/H1, свечной ТФ D1/W1/H1 по доступности, слои, добавление зоны, fullscreen в overflow. Режим анализа и ТФ свечей — разные атрибуты. Временной диапазон и слои не должны сбрасываться при обновлении данных. График сохраняет pan/zoom, шкалу, crosshair и привязку к событиям.

Правый инспектор:

- **Сценарий:** направление, стадия, основание и точное время; зона входа или причина отсутствия; PD, 50%, признак предварительности; условие отмены; наблюдение; предпочтительный вход, если доступен; основания и качество данных в details.
- **Зоны:** актуальные / кандидаты / архив, счётчики, поиск/фильтр типа и ТФ/положения, обновление порядка, карточки/таблица, группировка зон, detail. SSL/BSL — уровни, диапазоны — диапазоны. Сохранить состояния worked, rejected, taken, converted, archived и различие review/market lifecycle.
- **Контекст:** краткое наблюдение, blockers/unknown, freshness и ссылка в контекст рынка. Не повторять всю страницу условий.

Нижняя область: зоны сценария и события выбранного актива; в компактном режиме — вкладки, desktop допускает регулируемую высоту. Перетаскиваемые splitters доступны клавиатурой, имеют min/max и сохраняют размеры локально.

### S03. Структура H1

Тот же shell и instrument. Не отдельная глобальная страница. Доступны все текущие точки HH/HL/LH/LL, BOS/SMS, ожидаемые уровни, H1 OB/FVG/BSL/SSL, зоны HTF, HTF-идеи, текущий/исторический сценарий и causal chain.

Слои — desktop popover или закрепляемая панель шириной 320–400 px, mobile bottom sheet. Три группы: контекст; структура; отображение. Каждый flag из реестра имеет отдельный переключатель. В макете некоторые flags сведены в демонстрационные подписи; **в реализации это запрещено**, например OB/FVG, BSL/SSL, кандидаты HTF/H1 и история HTF/H1 управляются отдельно.

Количество точек: последние 20 / история / скрыть. Внутренние и неоднозначные точки — отдельная диагностика, по умолчанию выключена при отсутствии сохранённого выбора. Все таймфреймы, середины, подписи, candidates, eligible-only, HTF context, idea selection и close idea сохраняются. «Вне экрана: N» приводит к объектам без потери текущего выбора.

Дефолт компактного отображения не меняет расчёт и не скрывает факт существования объектов: число скрытых/вне экрана доступно. Если пользователь уже настроил слои, сохранить их выбор. Вид «только актуальное» — UI-фильтр, не очистка истории.

### S04. Проверка

Очередь → график основания → инспектор задачи. Фильтр ТФ, счётчик прогресса, экспорт всех проверенных. Задача показывает объект, тип, ТФ, границы, инструмент, объяснение правила и состояние жизненного цикла.

Действия обязаны сохранить исходные значения: `correct`, `wrong_type`, `fix_boundaries`, `wrong_base`, `now_irrelevant`, `already_breaker`, `no_context`. Основные: подтвердить, отклонить. Остальные — доступное меню, а не удалённая функциональность. Comment сохраняется при обновлении и ошибке. История событий, решений, оценок и boundary corrections доступна.

Сохранение блокирует повторное нажатие; переход к следующей задаче только после успешного ответа и отображения результата геометрии/цикла. 422 — сообщение рядом с полем; timeout — неизвестность результата, перечитать detail перед повтором. Нельзя показывать успешное решение до ответа сервера. Не добавлять фиктивный «Отменить» без поддержанного механизма отмены.

В пустой очереди не рисовать ложную задачу. В макете пример OB #18 существует отдельно и обозначен как демо.

### S05. Журнал

Типы: все / рынок / решения / доставка. Отдельно instrument, диапазон дат, поиск текста при доступности API. Сортировка по occurred_at, стабильный tie-break ID; timezone МСК с возможностью увидеть исходный timestamp.

Строка: время, инструмент, тип и понятное название, ключевое значение, доставка/проверка при наличии, переход к detail и свече. Группировать только presentation: одинаковые instrument + event kind + zone/scenario + значимые payload + временное окно. Окно конфигурируемое UI, по умолчанию 60 секунд; не группировать разные направления, значения, исходы доставки или решения. Каждая группа раскрывает все оригиналы с ID и временем; количество отображается явно. Не сортировать задним числом recovered события так, будто они доставлены своевременно.

Для длинного списка использовать существующую пагинацию или виртуализацию доступных записей, без потери истории. Live additions не сдвигают выбранную строку; при чтении прошлого показывать «Новые записи: N» вместо прыжка наверх.

### S06–S09. Контекст рынка

**Состояние:** текущая ситуация, service_line и risk_note; funding.kind/sign, liquidation.share/quality, OI direction/quality. Доля лонгов оформляется в %, исходная точность доступна; не отображать как вероятность. Источники и freshness — отдельный блок.

Все gates A/B/V/G и их checks остаются видимыми: выполнено / не выполнено / неизвестно; blocked / not_applicable и другие исходные состояния маппятся на язык UI. Blocking reasons и unknown_dependencies различаются. Сводка не заменяет полный перечень условий. Все situations доступны, включая experimental отметки.

**Лента:** стабильный словарь rule_id и transition, понятное название, occurred_at, подробности. Неизвестный код показывать как «Неизвестное событие» + исходный код; не пропускать запись. MORNING_DIGEST, POST_HIGH_LONG_CASCADE, CASCADE_OI_RISING_RISK, RED_WIDE_DAY_REBOUND_WATCH, RED_STREAK_REBOUND_WATCH имеют отдельные названия. Не подменять occurred_at временем доставки.

**Календарь:** факты utc_date, week_of_month, month_end_card, chain и note. Месячная сетка — новая визуальная проекция существующей даты, не источник дополнительных вычисленных торговых сигналов. Если source date отличается от локального дня, показать обе подписи; не исправлять datum автоматически. Empty_reason виден как отсутствие данных, а не «сезонная цепочка неактивна».

**Правила:** все IDs, text, class и note из API. Для LIQ01 строго >60%; LIQ02 ≥1,9 медианы 90 предыдущих дней; OI02 действует до конца c+7; FR03 относится к выплаченной 8h ставке. Нельзя заменять strict > на ≥ или делать observed funding settled. study note об отсутствии проверки процентов/t-статистики сохраняется. Правила доступны только для чтения, если API не поддерживает редактирование.

### S10. Настройки

Навигация по четырём разделам; поле имеет краткий label, единицу, текущее значение и раскрываемое объяснение при необходимости. Нельзя терять существующие поля из `SETTINGS_META`, даже если не показаны в макете.

Группы notification/analysis/experimental/deprecated и применимость берутся из API; не поддерживать второй независимый список параметров. Числовые поля имеют серверные min/max/тип; доли можно показывать процентами через явный двунаправленный адаптер. 900 секунд → 15 минут только для digest, с точным обратным преобразованием; 120 часов остаются часами.

Список H1 kinds заменить multi-select с теми же ключами; неизвестные сохранённые ключи не удалять. Экспериментальные параметры имеют маркировку «Не калибровано» и исходную подсказку. Deprecated значения не отправлять повторно без необходимости.

Кнопки сохранить/отменить включаются при dirty. Сохранение → saving → сохранено / ошибка; если запущен реальный пересчёт, отдельный статус running/completed/failed. Сохранение файла и успешность пересчёта — разные события. Ошибки API сохраняют draft. При уходе с dirty формы — предупреждение о потере draft, без блокировки обычной навигации после сохранения.

Тема dark/light/system применима сразу, сохраняется в том же `lf:theme` с миграцией, не запускает пересчёт. Реальный timezone остаётся поддерживаемым контрактом; не добавлять изменяемый selector, если сервер не поддерживает смену. Токены/секреты не выводятся в UI и экспорт.

Активы: все текущие инструменты и площадки, including два разных HYPE, не объединять по одному тикеру. Переключение после ответа сервера; обратимое действие сопровождается точным описанием эффекта. Добавление инструмента через существующий API сохраняется, если доступно в текущем продукте; не ограничить интерфейс шестью примерными строками.

### S11. Скринер

Основной вид — таблица: символ/биржа, стадия, последнее событие, закрытие D1 с датой, расстояние до входа, freshness; дополнительные столбцы в «Колонки». Счётчики buckets — данные API, а не длина текущей загруженной страницы.

Все существующие buckets `eligible`, `new_entries`, `awaiting_retest`, `review`, `history` сохраняются. «Активный» не означает доступный вход. Расширенные фильтры: venue, rank min/max, age min/max, drawdown min/max, structure, stage; поиск ticker/name/pair; все текущие сортировки. Сохранить min и max для каждого диапазона. В макете показан только фрагмент расширенных фильтров.

Поиск debounce 200–300 ms; сброс фильтров всегда доступен. Выбор актива не исчезает при обновлении списка; если он отфильтрован, показать причину и «Показать в списке». Рассчитывать ranking только существующим способом; расстояние явно обозначено как ранжирование.

Показать run-status, актуальность snapshot, ошибки обработки, повтор загрузки и пересчёт. Recalc не запускается самим открытием страницы. Таблица и графический просмотр переключаемы; возможность последовательного просмотра в боковом списке сохраняется.

### S12. Детали сетапа альткоина

Отдельный фокус: график + инспектор; возврат сохраняет фильтры, выбранный bucket, сортировку и строку. Setups и candidates остаются разными субъектами API.

Все текущие графические режимы: сетап / история / без событий. D1/W1, 180D, весь диапазон, вся история, fullscreen, auto-scale, PNG, PNG 2×. Слои: range L/U/M, entries/retest, manipulation, targets modes, cancel K, reverse structure. W1 — агрегирование D1, незакрытая W1 явно обозначена; события считаются по D1.

Инспектор: current stage, basis, entries A/B с историческими timestamps, цели и исходы, cancellation, retest deadline, distance, why found. События выбранного сетапа фильтруются по типу и датам; переход к свече; показать все/скрыть sidebar/card. Не называть исторические A/B «текущим входом».

Редактор диапазона: L/U, начало и конец базы, комментарий, preview → revision save, список ревизий и restore-auto. Сохранить subject_kind/subject_id, validations и rollback сервером. Кнопка Save недоступна до успешного актуального preview; любое изменение сбрасывает preview. Не вычислять M на клиенте как замену подтверждённому ответу. K ≤ 0 не рисуется линией, причина видима текстом.

### S13–S16. Общие overlays

- Добавление зоны: рисование на графике двумя кликами или числовая форма; диапазон/уровень, lower/upper/level, bull/bear, D1/W1, типовое правило OB/FVG/нет, начало/якорь, имя, комментарий, отмена. Уровень L=U допустим по исходным правилам. Escape отменяет рисование.
- Коррекция границ: lower/upper, preview, optional anchor; datetime и выбор свечи, clear anchor; техническое время ms в details; ошибка рядом с формой. Не потерять существующий якорь на сохранении.
- Инспектор зоны: все события, assessments, reviews, boundary corrections, relationships, inner levels, reconciliation, preferred entry по доступности; возврат к предыдущему списку.
- Событие: исходные записи, payload в details, время возникновения/доставки, recovered/delayed, связанный chart context. Deep link должен открывать фактическое событие, не только выбранный asset.

## 8. Доступность и системные состояния

- WCAG 2.2 AA как цель приёмки: текст ≥4,5:1, крупный текст ≥3:1, значимые интерактивные контуры ≥3:1. Отдельная проверка обеих тем, без заявления о сертификации макета.
- Клавиатура: логический порядок Tab, видимый focus, Enter/Space для действий, Escape для overlay, фокус внутри dialog и возврат к инициатору. Tabs/segmented имеют aria-selected/aria-pressed в зависимости от паттерна.
- Таблицы — реальные table/th и aria-sort; выбор строки доступен отдельной кнопкой/ссылкой, не только click-handler на tr. В макете tr демонстрационные; production обязан устранить этот упрощённый паттерн.
- График имеет текстовый эквивалент ключевых уровней и состояние загрузки. Подписи не только цветом; price и dates читаются screen reader.
- Loading: skeleton структуры, не нули. Empty: различать отсутствие объектов, пустой фильтр, отключённый анализ, недостаточную историю, отсутствие оценки. Error: источник, последняя успешная загрузка, Retry; stale: данные сохраняются с возрастом. Offline: баннер connection отдельно от качества каждой серии.
- Частичная недоступность не превращается в отсутствие сетапа или снятие запрета. Unknown ≠ false. Подтверждённая сервером геометрия ≠ рыночная актуальность.
- Toast не единственное место сообщения о сохранении/ошибке. Критичный status закреплён рядом с действием. Reduced motion; без анимаций цен, вызывающих мигание таблицы.

## 9. Реализация и производительность

Текущий стек: FastAPI, статические HTML/CSS/JS, Lightweight Charts 4.2.0. Не добавлять framework или обновлять библиотеку графика одновременно с редизайном без конкретного обоснования. Выделить общий shell, токены, форматирование и компоненты; `common.js` сохранить как точку API/auth или выделить совместимый adapter.

Сетевые операции — существующие endpoints из реестра. Fetch отменяется при смене instrument/bucket; поздний ответ другого инструмента не может перезаписать текущий экран. Использовать request generation или AbortController. WS connection, quote freshness, candle freshness и расчётные snapshots — отдельные потоки. При retry mutation проверить фактическое состояние, не выполнять повторную необратимую запись вслепую.

Денежные значения не менять из-за форматирования. API payloads сохраняют числа и enum; UI-словарь только переводит. Безопасный вывод textContent/escape, без вставки неэкранированных server strings. Токен не попадает в URL, console, screenshots или zip.

Предлагаемые бюджеты для локальной приёмки, не измеренные свойства текущей системы: переключение уже загруженной вкладки ≤100 ms; поиск на локальных 1000 строках ≤100 ms; отсутствие >50 ms длительных задач при обычном переключении; отсутствие скачков layout при quote updates. Измерять в описанной среде, серверные задержки отдельно. Виртуализировать большие журналы/таблицы по результатам профилирования, а не заранее усложнять маленькие списки.

## 10. Последовательность работ

1. Зафиксировать baseline: endpoints, screen controls, сценарии, deep links и текущие tests. Составить `FUNCTION_MAP`: функция → новый компонент → API → проверка.
2. Токены и общий shell, совместимость маршрутов и тем, типографика и status/freshness. Без миграции данных.
3. Обзор и настройки: единые поля, сохранение и статусы пересчёта. Проверить каждое поле реестра.
4. Рабочее место HTF/H1: inspector, layers, persisted chart state, событийные переходы, manual/bounds forms.
5. Проверка и журнал: все decisions, exports, audit, presentation groups.
6. Контекст рынка: все modes, словари, quality, gates, calendar UTC.
7. Скринер и детали: filters, buckets, range revisions, экспорт графика и return state.
8. Адаптивность, клавиатура, обе темы, реальные regression checks. Отчёт о расхождениях с макетом, только затем переключение пользовательского входа.

## 11. Критерии приёмки

- Все пункты `FUNCTIONAL_INVENTORY.md` сопоставлены новому UI или явно обоснованному совместимому входу; отсутствующие функции — блокер.
- Никаких изменений формул, строгих порогов, направления, временных окон, causal timestamps, lifecycle и схем БД ради дизайна.
- Обзор → актив → H1 → событие → журнал → назад сохраняет instrument, mode, выбранную идею и filters.
- Анализ актива и наблюдение за сценарием переключаются независимо; оба HYPE различимы по площадке/ID.
- Каждый HTF/H1 слой включается отдельно. Изменение visible layers не удаляет объект и не изменяет его state.
- Все семь review decisions, corrections, anchors и exports работают с реальными ответами; история не теряется.
- Скринер: все buckets, интервалы min/max, сортировки и hidden selection; детали: все режимы и слои; PNG/PNG2×; редактор preview/revision/restore-auto.
- Настройки: каждый серверный ключ сохранён; проценты и минуты обратно преобразуются точно; ошибки draft и 422 видны; recalculation status корректен.
- Coinglass H1 unavailable не становится check=false; funding observed не settled; UTC календаря не заменяется локальной датой.
- 360, 390, 768, 1024, 1440, 1920 px: body без horizontal overflow, local table scroll разрешён, формы/menus не обрезаны; touch ≥44 px в production.
- Обе темы читаемы; keyboard-only сценарий завершает выбор, проверку и сохранение формы; screen reader получает названия, ошибки и выбранность.
- Проверены loading, empty, partial failure, offline, stale, 401/422/500, duplicate submission и поздние ответы.
- Existing relevant tests проходят; новые regression tests проверяют реальные риски (decisions, единицы, race, state, routing), а не каждый CSS-selector.

## 12. Что именно демонстрирует макет

Работают локально: семь основных разделов; HTF/H1 переключение; вкладки инспектора; четыре режима контекста; четыре секции настроек; theme switch; поиск восьми строк; часть bucket filters; review example and result; dialogs и базовая проверка границ; наблюдение/анализ; dirty/save demo; JSON demo export.

Показаны как структура/упрощение: числовые счётчики, расширенные фильтры, слои, реальные свечи и pan/zoom, event anchor, переходы на targets, run processing, server save/rollback, PNG, revision preview, virtualized journal, все детальные параметры. Они перечислены в ТЗ и реестре и обязательны для будущей реализации. Демонстрация не является доказательством работы этих функций.

`prototype.js` не переносить в production как источник бизнес-логики. Синтетические свечи и snapshot цифры не подключать к реальному обзору. Функции, которые в макете показывают toast вместо работы, должны иметь полноценную реализацию через действующий контракт.
