# План редизайна страницы «Альткоины»

Дата: 7 октября 2026. Статус: предложение для реализации.

Связанное ТЗ: [очистка графика и отображение событий](Altcoins_Chart_Declutter_Spec_RU.md).

## 1. Цель и границы

Превратить страницу из широкой таблицы параметров в рабочее место: выбрать монету → понять состояние сетапа → изучить читаемый график → проверить основание и условия завершения.

Основание: предоставленный скриншот и текущие `app/web/static/alt.html`, `alt.js`, `style.css`, `app/web/alt_api.py`, `app/services/alt_overview.py`, модели и части `app/alt/engine.py`. Приложение в браузере не запускалось; замечания к интерфейсу основаны на изображении и коде. Рыночная корректность стратегии этим документом не оценивается.

Результат этой задачи — план и ТЗ. Изменения интерфейса и движка выполняются отдельным этапом. Существующие документы общего редизайна сохраняются; этот план уточняет работу раздела «Альткоины».

## 2. Что сейчас мешает

| Проблема | Основание | Решение |
|---|---|---|
| В таблице одновременно 21 колонка, включая исходные параметры и технические сведения | `alt.html`, `renderTable()` | Компактный список для выбора; полные параметры в карточке и отдельном режиме таблицы |
| Таблица занимает верхнюю треть экрана; выбранный актив и график далеко от места выбора | Скриншот, `.alt-layout` | Список слева, график в центре, детали справа |
| Заголовок графика оказывается большим пустым блоком слева, длинное пояснение K — справа | Скриншот; `.chart-block` наследует горизонтальный `display:flex`, внутри идут toolbar, container и note | Задать отдельную вертикальную компоновку графика; предупреждение перенести в карточку |
| Сотни старых BOS, SMS, SSL и обратных событий закрывают свечи | Скриншот; цикл по всем `d.structure_events` в `renderChart()` | Режим «Сетап» с выборочными событиями; вся история доступна по запросу |
| При каждом обновлении вызывается `fitContent()` | `renderChart()` вызывается после повторной загрузки выбранного сетапа | Сохранять положение графика; обзор истории — отдельная команда |
| Вся история от ATH сжимает текущую область накопления | `_detail_candles()` и `fitContent()` | Начальный вид последних 180 D1, команды «Весь диапазон» и «Вся история» |
| Флаги «BOS/SMS SSL выход ретест» плохо объясняют текущее состояние | `flagsText()` выводит агрегированные флаги без дат | Краткий статус + последнее событие с датой; история отдельно |
| У кнопки «Почему найдено» скрыта почти вся содержательная информация | `renderWhy()` и модальное окно | Краткое объяснение постоянно в карточке; формулы и версии раскрываются |
| «Close», «K дост.», «Deadline», `as_of`, `run` требуют расшифровки | Скриншот, шаблон страницы | Понятные подписи и единицы; технические сведения в раскрываемом разделе |
| Выбор бирж строится из уже отфильтрованных строк и может сброситься | `loadTable()` | Независимый список бирж; фильтр сохраняется даже при нулевом результате |
| Ответы списка могут прийти в обратном порядке | У `loadTable()` нет защиты, аналогичной `reqSeq` у выбранной строки | Отмена устаревших запросов или проверка номера запроса |
| Тёмный фон графика жёстко задан при цветах сетки/текста из текущей темы | `initChart()` | Цельная палитра для светлой и тёмной тем |

## 3. Предлагаемая компоновка

```text
Альткоины D1                       Данные на 07.10, 03:00 МСК · Обновлены
Все активные · Новые входы · Ретест · Проверка · История     Фильтры (2)
┌────────────────┬─────────────────────────────────┬───────────────────┐
│ Поиск монеты   │ HBAR · HBARUSDT · Binance · D1   │ Состояние сетапа  │
│ Сортировка     │ Сетап | История | Без событий    │ Основание + дата  │
│                │ Слои · 180D · Диапазон · История │                   │
│ HBAR           │                                 │ Вход A / B        │
│ Новый вход     │         БОЛЬШОЙ ГРАФИК          │ Цели и отмена     │
│ До входа …%    │                                 │ Условия / срок    │
│ Последнее …    │                                 │                   │
│                │                                 │ Почему найдено ▾  │
│ RENDER         │                                 │ Параметры ▾       │
│ Ожидает …      │                                 │ Данные и версии ▾ │
├────────────────┴─────────────────────────────────┴───────────────────┤
│ События выбранного сетапа ▾  ·  переход к свече  ·  фильтр типов       │
└──────────────────────────────────────────────────────────────────────┘
```

Это схема расположения, а не фиксированный визуальный макет. Значения берутся из актуального снимка; пример не задаёт торговые условия.

### 3.1. Размеры и адаптивность

- От 1440 CSS px: список 280 px, карточка 300 px, график занимает остаток; обе боковые панели сворачиваются. При ширине 1440 px центральная область — не менее 760 px с учётом отступов.
- От 1100 до 1439 px: список 260 px, карточка открывается в выдвижной панели; график остаётся основным рабочим местом.
- От 768 до 1099 px: список и график — переключаемые представления; выбранный актив виден в заголовке. Карточка открывается отдельной панелью.
- До 767 px: сначала список, после выбора — график и краткая карточка, с явной кнопкой возврата. Полная таблица допускает горизонтальную прокрутку внутри своего контейнера.
- На desktop высота области графика — не менее 420 px при viewport высотой от 800 px; на мобильном — не менее 300 px. При малой высоте разрешена вертикальная прокрутка страницы.
- Панель инструментов всегда находится над графиком. График не делит горизонтальную строку с предупреждением или заголовком.

### 3.2. Список монет

Одна строка/карточка содержит: тикер; пару и биржу вторым уровнем; стадию; расстояние до входа, если оно определено; последнее значимое событие с датой. Детальные цены L/U/M/W, ATH, цели и K здесь не нужны.

Высота строки 56–64 px, основной текст 14 px. Выбранная строка имеет фон, рамку/индикатор и доступное состояние выбора. Цвет дополняет текст, а не заменяет его.

Поиск по тикеру, имени и паре. Основные вкладки: «Все активные», «Новые входы», «Ожидание ретеста», «Требуют проверки», «История». «Зрелые» и «Формирующиеся» остаются доступными в фильтре стадии.

«Все активные» соответствует существующему `eligible`: активные строки без стадии проверки. В подсказке пояснить состав группы; название «Подходящие» не должно создавать впечатление, что все эти монеты готовы к входу.

Сортировка по умолчанию сохраняет серверный порядок приоритетов. Дополнительные режимы: расстояние до входа, ранг CMC, возраст диапазона. Для числового порядка значения `null` идут последними; одинаковые значения стабилизируются идентификатором объекта. Ранг CMC подписать как ранг капитализации, не оценку качества сетапа.

### 3.3. Фильтры

В основной строке оставить поиск, вкладки стадий, биржу и кнопку «Фильтры». В раскрываемой панели: ранг CMC, возраст диапазона, историческое падение от ATH, структурные события. Применённые фильтры показать чипами с возможностью снять каждый.

Ввести подписи и единицы вместо одних placeholder. Проверять неотрицательные значения, падение 0–100%, нижнюю границу ≤ верхней. Ошибка у поля блокирует применение. Использовать уже доступные `age_max` и `dd_max` при необходимости двухсторонних диапазонов.

Разделить кнопку «Сбросить фильтры» и пользовательские настройки отображения. Сброс фильтров не меняет слои, масштаб графика и размеры панелей.

Счётчики вкладок обозначают общее число в группе до вторичных фильтров, как в текущем API; над списком — «Показано N» после фильтрации. Список бирж загружается независимо от текущей выборки.

### 3.4. Карточка выбранного сетапа

Порядок информации:

1. **Текущее состояние:** стадия, последнее значимое событие, его дата. Для завершённого сетапа — причина и дата завершения.
2. **Основание:** первое подтверждение и ссылка на свечу. Если подтверждения нет — явное «Диапазон формируется / подтверждения ещё нет».
3. **Входы A/B:** цена или зона, дата зафиксированной возможности, расстояние и условия по существующим правилам. Исторически зафиксированный вход не подписывать как доступный сейчас без отдельного признака актуальности.
4. **Цели:** TP1–TP4 с ценами и состоянием «достигнута / ожидается / пройдена до подтверждения».
5. **Отмена:** K, действующий режим проверки, пояснение при недостижимом уровне. Неположительный K: «Расчётный уровень отмены ≤ 0; на графике не отображается». Формулу и исходные значения показать при раскрытии.
6. **Срок ретеста:** абсолютная дата МСК и оставшееся время относительно момента просмотра, с отметкой свежести расчёта. После завершения — факт истечения, а не отрицательный обратный отсчёт.
7. **Почему найдено:** опоры, подтверждение, диапазон и краткое объяснение. Формулы, классификатор, история расширений, версии и источник — раскрываемые разделы.

Человеческие названия брать из единого отображения существующих состояний. Не сочинять «покупать», «надёжность 90%» или прогноз доходности. A/B должны соответствовать фактическим правилам движка: комментарии модели и отдельные UI-подписи сейчас требуют сверки, переименование без неё недопустимо.

### 3.5. График

Начальный режим «Сетап»: свечи, диапазон и необходимая разметка выбранного сценария. Правила отбора событий, целей, масштаба, группировки и истории определены в связанном ТЗ.

Панель: режим событий, «Слои», «180D», «Весь диапазон», «Вся история», «Развернуть график». Таймфрейм подписан D1; смену таймфрейма этот этап не добавляет.

Над графиком: актив, биржа, пара, цена последней закрытой D1 и дата свечи. Подпись «Цена закрытия D1» обязательна: live-котировки в текущем контракте нет.

Цены с точностью, достаточной для различения близких уровней; большие и малые значения не округлять до одинаковых подписей. Цветовая схема графика соответствует выбранной теме. Предупреждения и формулы не занимают боковую часть графика.

### 3.6. Полная таблица

Режим «Таблица» доступен отдельным переключателем для сравнения монет. По умолчанию 7 колонок: монета/источник, стадия, закрытие D1, расстояние до входа, возраст диапазона, падение от ATH, последнее событие.

Остальные исходные колонки доступны через «Колонки»: значения не исчезают из продукта. Первая колонка и заголовок закреплены, числовые значения выровнены, порядок и набор колонок сохраняются. Выбор строки открывает то же рабочее место, с тем же объектом и фильтрами.

### 3.7. Свежесть и состояния загрузки

В верхней строке: «Данные на … МСК», состояние последней обработки и индикатор проблем. Последний/следующий запуск, число обработанных, пропуски, ошибки и ручной пересчёт — в раскрываемой панели «Обработка».

Раздельно показывать подключение WebSocket и свежесть свечей/расчётов. Устаревший снимок или ошибка источника остаются заметными без открытия панели.

Предусмотреть: первичную загрузку; обновление с сохранением последнего снимка; отсутствие результатов фильтра; отсутствие свечей; устаревшие данные; ошибку запроса; удалённый/недоступный объект. Для ошибки дать повторную загрузку соответствующего блока. Нулевой результат фильтра не подписывать как отсутствие сетапов во всей системе.

При выборе другой строки немедленно менять заголовок и показывать загрузку; прежние детали не должны выглядеть данными нового актива. Поздние ответы списка и карточки игнорировать.

## 4. Сохранение рабочего контекста

- Сохранять фильтры, сортировку, слои и режим таблицы локально с версией схемы настроек.
- Выбранный объект задавать `kind + id`, а не только активом. Добавить точный deep link `?setup=ID` / `?candidate=ID`; существующий `?asset=CMC_ID` оставить совместимым.
- Приоритет ссылки: точный объект → существующая ссылка актива → восстановленный локальный выбор → первый доступный объект списка. Несуществующий точный объект даёт явную ошибку без тихой подмены.
- Если объект по ссылке скрыт фильтром, показать его с сообщением «Выбранный сетап вне текущего фильтра» и действием «Показать в списке».
- Обновление по WebSocket не меняет выбранный объект, прокрутку списка или ручной масштаб графика.
- Стрелки вверх/вниз выбирают соседнюю строку при фокусе в списке; Enter открывает детали; Escape закрывает панель. Не перехватывать клавиши внутри полей и на графике.
- Закрытие панелей возвращает фокус к вызвавшему контролу. Кнопки, фильтры и строки работают с клавиатуры; интерактивные элементы имеют подписи и видимый фокус.

## 5. План реализации

| Этап | Приоритет | Работа | Готовый результат |
|---|---|---|---|
| 1. Освободить график | P0 | Вертикальная компоновка toolbar/chart; K в карточке; выборочный вывод событий; убрать повторный `fitContent()`; цельная тема | Текущий график читается без полного переписывания страницы |
| 2. Организовать рабочее место | P1 | Список слева, график в центре, карточка справа; компактная сводка и адаптивность | Основной анализ выполняется на одном экране |
| 3. Упростить поиск и сравнение | P1 | Поиск, фильтры с чипами, стабильная биржа, сортировки, защита от гонок, режим полной таблицы | Можно быстро выбрать и сравнить монеты |
| 4. Сделать историю управляемой | P1 | Журнал событий, переход к свече, точные ссылки, сохранение настроек, режим истории | Любое скрытое событие можно найти и проверить |
| 5. Проверить удобство | P1 | Размеры экранов, темы, клавиатура, состояния ошибок; проверка на примере HBAR и плотной истории | Выполнены критерии обоих документов |

Этапы 1 и базовая часть журнала из этапа 4 внедряются вместе: после скрытия событий пользователь сразу имеет способ открыть их. Новые серверные поля и компоненты нормализации сначала добавляются совместимо со старым UI.

## 6. Критерии приёмки редизайна

1. На 1440×900 и 1920×1080 при масштабе браузера 100% список, график и краткая карточка видны вместе; основной режим не требует горизонтальной прокрутки страницы.
2. Заголовок графика находится сверху; предупреждение K не отнимает ширину области свечей. Выполнены размеры из §3.1.
3. На 1366×768 карточка сворачивается; на 1024×768, 768×1024 и 390×844 выбор актива и возврат к списку работают без перекрытия управления.
4. В течение 10 секунд после загрузки на сценарной проверке пользователь находит стадию, основание, актуальные условия входа, цели и отмену. Проверять на пяти репрезентативных объектах: формирующийся, подтверждённый, ожидающий ретест, завершённый, с проблемой данных. Это целевой UX-показатель, а не уже измеренный результат.
5. «Цена закрытия D1» имеет дату; подключение WS не выдаётся за свежесть данных; проблемы источника видны сразу.
6. Фильтр биржи сохраняется при пустом результате; быстрая смена фильтров и актива не приводит к выводу старого ответа.
7. При WS-обновлении сохраняются выбор, прокрутка и ручной масштаб; точная ссылка открывает нужный исторический сетап того же актива.
8. Старые 21 колонка остаются доступны в режиме таблицы/карточке. Названия, единицы и null-значения однозначны.
9. Светлая и тёмная темы читаемы; статус не определяется одним цветом. Основной сценарий доступен с клавиатуры.
10. Выполнены критерии очистки графика из отдельного ТЗ; скрытые события доступны в журнале.
