# ТЗ: последние 20 точек H1, структурные изменения и зоны LTF

Дата: 9 октября 2026. Статус: план исправления; код приложения этим документом не изменён.

Основание: запрос пользователя — уменьшить количество LH/LL на часовом графике, показывать последние 20 точек, рисовать BOS/SMS и переходы HH/HL ↔ LH/LL, восстановить отображение OB/FVG/BSL/SSL на LTF.

Связанный документ: [точные сообщения о состоянии рынка](Market_State_Messaging_Spec_RU_2026_10_08.md). Это ТЗ распространяется на H1 основного рабочего места и отдельную страницу LTF. Наличие выбранного HTF-контекста не должно определять наличие общей часовой разметки.

## 1. Ожидаемый результат

При открытии H1 пользователь видит:

- Последние **20 подтверждённых структурных точек суммарно**, с подписями HH, HL, LH, LL.
- Подтверждённые BOS/SMS: направление, пробитый уровень, связь с опорой и свечой подтверждения.
- Понятную смену структуры вверх/вниз; неподтверждённый переход не выдан за завершённый.
- Актуальные часовые OB/FVG как области и BSL/SSL как уровни, даже когда торговый сценарий ещё не открыт.
- Отдельное выделение зон, пригодных для текущего сценария. Видимость зоны не означает разрешение входа.

Лимит 20 относится только к подписям структурных точек. Он не ограничивает историю вычислений, количество опор, сохранение событий или поиск зон.

## 2. Что подтверждено в текущем коде

| Место | Наблюдение | Следствие |
|---|---|---|
| app.js, loadH1Markers() | Все confirmed pivots передаются в setMarkers(), ограничения 20 нет | История заполняет график подписями |
| overview.observation_chart_layers() | structure_events выбираются из активного либо последнего сценария наблюдения | События других структурных эпизодов не образуют общую историю инструмента |
| overview.instrument_structure() | Без подходящего context_id остаются пустые entries и structure_events | Общие pivots видны, но события и зоны могут отсутствовать |
| ltf.js, entryList() | Основные зоны берутся из entries и eligible_entries; исключённые добавляются только отдельным переключателем | Обнаруженная зона, не допущенная сценарием, может быть невидима |
| ltf.js, drawLtfLayers() | По умолчанию берётся последнее структурное событие; все — через «Подробную структуру» | Показ событий связан с настройкой подробных pivots |
| app.js / ltf.js, линии BOS/SMS | Начало восстанавливается из порядка ref_pivot_ids; есть запасные варианты без точной опоры | Возможны нулевой отрезок или условное начало; нужна явная геометрия события |

Это подтверждённые ограничения путей данных. Для конкретной пропавшей зоны при реализации дополнительно проследить цепочку «детектор → БД → API → фильтры → координаты → отрисовка». Нельзя заранее считать, что все четыре типа отсутствуют по одной причине.

## 3. Последние 20 структурных точек

### S01. Правило отбора

1. Брать точки выбранного инструмента и H1, доступные на as_of: state=confirmed, confirmed_at ≤ as_of, role ∈ {HH, HL, LH, LL}.
2. Исключать superseded-записи и дубли одной логической опоры текущей версии расчёта.
3. Упорядочить по времени экстремума pivot_at; равенства разрешать стабильным идентификатором. Выбрать последние 20, отрисовать в хронологическом порядке.
4. Лимит общий, а не 20 каждого типа. Если точек меньше — показать имеющиеся.
5. Internal_high/internal_low, none и ambiguous не входят в стандартный набор; доступны в режиме диагностики.
6. На историческом as_of использовать известную тогда роль, а не финальную роль из будущего.

По умолчанию «последние» означает последние на момент анализа, **не последние 20 в произвольном видимом окне**. Обычный скролл/zoom не меняет выбранные 20. Для просмотра прошлого пользователь включает историческую структуру либо задаёт as_of.

### S02. Управление

Переключатель «Точки структуры»: «Последние 20» (по умолчанию), «История», «Скрыть». Дополнительный выключенный переключатель «Внутренние и неоднозначные точки» относится к диагностике.

История загружается по видимому интервалу с запасом, а не материализует все маркеры всей БД одновременно. Настройки сохраняются отдельно от параметров детектора. Оба H1-экрана используют одно правило и одинаковый стандартный режим.

### S03. Новая точка

После подтверждения новой опоры самая старая из отображаемых исчезает, новая добавляется. Незакрытая свеча не вытесняет подтверждённую точку. Перерисовка не сбрасывает масштаб и положение графика.

Полные опоры остаются в данных расчёта. Скрытие старой подписи не удаляет её из диапазона, зоны или BOS/SMS. При выборе события допускается временно выделить его старую опору отдельным слоем; это не расширяет постоянно набор 20.

## 4. BOS/SMS и переходы структуры

### B01. Событие и последовательность ролей — разные факты

Пользовательский смысл: видеть смену восходящей структуры HH/HL на нисходящую LH/LL и обратно.

Отметка BOS/SMS появляется только при выполнении действующих правил структурной машины: подтверждённые опоры, причинная последовательность и закрытие H1 строго за соответствующим уровнем. Тень, открытая свеча и Close == level не подтверждают пробой.

- Из восходящей структуры закрытие ниже опорного HL может подтвердить медвежий BOS; SMS использует внутренний уровень и собственные предпосылки.
- Из нисходящей структуры закрытие выше опорного LH может подтвердить бычий BOS; SMS — зеркально по внутреннему уровню.
- Сформированная позднее пара LH→LL или HL→HH подтверждает новую последовательность опор. Её появление не переносит время BOS/SMS назад или вперёд.
- BOS может также подтверждать продолжение уже действующей структуры; каждый BOS не называть разворотом.

Не превращать простое соседство двух текстовых меток на графике в самостоятельный детектор BOS/SMS.

### B02. Общая структура инструмента

Рассчитывать и отдавать подтверждённые структурные события H1 независимо от наличия observation/scenario. Использовать тот же детерминированный механизм пробоев; не создавать отдельные несовместимые правила для графика.

Событие общей структуры может быть связано с одним или несколькими сценариями. Оно не открывает торговый сценарий автоматически: для сценария сохраняются правила HTF-контекста и допуска.

Смена/закрытие контекста не стирает исторический BOS/SMS инструмента. При миграции связать старые scenario-события с общими фактами; не объединять разные события только по совпадению цены.

### B03. Отрисовка

- Горизонтальный отрезок: от времени исходной опоры пробиваемого уровня до свечи пробоя, на точной цене break_level.
- Подпись на графике обязательна: «BOS ↑», «BOS ↓», «SMS ↑», «SMS ↓». Одного tooltip недостаточно.
- Конец отрезка привязан к свече, подтверждение — к времени её закрытия; оба времени доступны в карточке события.
- Направление обозначено цветом и стрелкой; BOS/SMS различаются подписью/стилем.
- Если опора вне экрана, отрезок обрезается границей viewport с признаком продолжения. Начало не выдумывается как «минус 10 свечей».
- Если происхождение legacy-события неизвестно, показать маркер на подтверждающей свече: «Исходная опора не восстановлена». Не рисовать недостоверный отрезок.
- При BOS и сопутствующем SMS на одной свече сохранять оба факта, объединять визуальную подпись либо разносить её. Не создавать два перекрывающихся одинаковых текста.
- Ожидаемые условия — отдельный отключаемый пунктир с подписью «Ожидаемый…». Они не выглядят подтверждёнными событиями.

### B04. Режимы и переход

Переключатель «BOS/SMS» включён по умолчанию и независим от «Точки структуры». Показывать события видимого интервала с необходимыми опорами; 20-точечный лимит на них не действует. При наложениях группировать подписи с раскрытием всех событий, не удалять факты.

Карточка события: вид, направление, уровень, опора, время закрытия, время обнаружения, состояние структуры до/после, ссылки на сценарии.

На смене структуры показывать проверяемую стадию:

| Состояние | Подпись |
|---|---|
| Слом вниз подтверждён, новая пара ещё не готова | «Слом вниз подтверждён; ждём нисходящую последовательность опор» |
| После слома подтверждена связанная LH→LL | «Нисходящая структура подтверждена: LH → LL» |
| Слом вверх подтверждён, новая пара ещё не готова | «Слом вверх подтверждён; ждём восходящую последовательность опор» |
| После слома подтверждена связанная HL→HH | «Восходящая структура подтверждена: HL → HH» |
| Структура неоднозначна | «Направление структуры не подтверждено» |

Для вывода «новая пара подтверждена» использовать связи и эпоху структурной машины, а не любые две последние точки. Если структурная машина ещё не предоставляет такое состояние, добавить его явно; не вычислять во фронтенде по строкам ролей.

## 5. OB/FVG/BSL/SSL на LTF

### Z01. Разделить обнаружение и допуск

Ввести два независимых слоя:

1. **Зоны H1 инструмента:** все обнаруженные и действующие объекты в области просмотра; не требуют сценария.
2. **Пригодность для выбранного сценария:** надстройка над теми же объектами — eligible / excluded / not_evaluated с причиной.

До открытия сценария зона отображается с пометкой «Пригодность для сценария не оценивалась», а не «Пригодна» или «Исключена». Зона вне Premium/Discount остаётся видимой в общем слое; запрет входа не равен завершению её lifecycle.

Если нынешний расчёт создаёт объект только внутри сценария, вынести обнаружение в общий расчёт H1 на существующих правилах и отдельно связывать объект со сценарием. Не переименовывать старые PRB в OB для заполнения слоя. Автоматический HTF-scanner на H1 может использовать собственную PRB-семантику; канонический источник H1 OB — правила LTF OB с явной provenance.

### Z02. Правила для четырёх типов

| Тип | Геометрия | Подпись и состояние |
|---|---|---|
| OB H1 | Прямоугольник по полным L/U основания | «OB H1» + направление; кандидат отличается от подтверждённого |
| FVG H1 | Прямоугольник по полным границам FVG | «FVG H1» + направление; частичное заполнение не скрывает зону |
| BSL H1 | Горизонтальная линия на уровне | «BSL H1»; отдельно действующий, пересечённый, исход возврата |
| SSL H1 | Горизонтальная линия на уровне | «SSL H1»; те же независимые состояния |

BSL/SSL не пропадают из-за нулевой ширины ценового диапазона. Полные границы OB/FVG не обрезать до половины Premium/Discount; принадлежность показывать стилем и причиной допуска.

### Z03. Временная геометрия и актуальность

Хранить отдельно время основания, подтверждения, начала рисунка, теста и завершения. До подтверждения объект не показывается подтверждённым. На историческом as_of будущие объекты и их будущие состояния не доступны.

Действующую зону продолжать вправо до текущего края; завершённую заканчивать в фактическое время завершения. Конец lifecycle не вычисляется по последней видимой свече.

Сохранить существующие различия правил:

- OB: глубокий тест и запрет повторного входа не равны потере рыночной актуальности.
- FVG: полное заполнение завершает зону; частичное — отдельное состояние.
- BSL/SSL: пересечение уровня и подтверждённый возврат после него — разные факты.

После завершения объект доступен в историческом слое. Действующие правила показа недавно снятых уровней согласовать между двумя H1-экранами; если используется окно 7 дней, явно подписать его. Это окно отображения, а не продление действия уровня.

### Z04. Настройки по умолчанию

«Зоны H1» включены, внутри — OB/FVG/BSL/SSL включены. «Только пригодные для сценария» выключен. «Кандидаты», «Исторические зоны», «HTF-контекст» — отдельные настройки, не смешанные с типами H1.

Старые сохранённые настройки мигрировать без молчаливого сброса явно выбранных пользователем выключений. Для отсутствующих новых полей применять новые defaults.

### Z05. Наложения и причины пустого графика

- Слой зон находится под свечами, линии и подписи читаются поверх заливок. При наложении доступен список отдельных объектов, без изменения их реальной геометрии.
- Зона, начавшаяся левее экрана, рисуется, если её временной интервал пересекает viewport.
- Внешние зоны не сжимают автоматически цену до нечитаемого масштаба. Доступны счётчик «Вне экрана: N» и действие «Показать зону».
- Для выделенной зоны показать тип, ТФ, направление, время подтверждения, lifecycle, пригодность и причину.
- Выключение визуального слоя не меняет расчёт или уведомления.

Пустой слой должен иметь диагностируемую причину:

| Причина | Сообщение |
|---|---|
| Объекты не найдены после завершённого расчёта | «На выбранном участке подтверждённые зоны H1 не найдены» |
| Скрыты фильтром | «Скрыто фильтрами: N зон» + сброс фильтров |
| За пределами экрана | «N зон вне видимой области» |
| Данные/расчёт отсутствуют | «Зоны H1 ещё не рассчитаны: {причина}» |
| Запрос завершился ошибкой | «Не удалось загрузить зоны H1» + повтор |
| Нет сценария, включён фильтр пригодности | «Выбран фильтр пригодности, но сценарий не открыт» + показать все зоны H1 |

Не подменять ошибки загрузки пустым успешным массивом без диагностического статуса.

## 6. API и единый контракт слоёв

Расширить инструментальный endpoint структуры совместимо со старыми полями. Предусмотреть from/to/as_of и пагинацию истории. Снимок содержит instrument_id, timeframe=H1, источник, версии правил/данных, snapshot_id/state_version, as_of и курсоры расчёта.

Новые логические группы:

| Группа | Обязательное содержание |
|---|---|
| pivot_markers | 20 выбранных точек, их роли/доступность и параметры отбора |
| anchor_refs | Все необходимые опоры событий и диапазонов, независимо от лимита подписей |
| structural_events | Канонический ID, kind, direction, break_level, level_pivot_id, level_pivot_at, break_candle_open_time, confirmed_at, detected_at, эпоха и связи со сценариями |
| structure_transition | Подтверждённая/ожидаемая смена последовательности, направление, причинное событие и связанные опоры |
| detected_zones | Тип, H1, полная геометрия, formation/confirmation/display/lifecycle, provenance |
| scenario_admission | Ссылки на те же zone IDs, scenario_id, eligibility, причина, версия диапазона |
| layer_status | Рассчитано/загрузка/ошибка/нет данных; числа total, shown, filtered, outside_view |

Числа shown/filtered/outside_view должны относиться к одному выбранному интервалу и явно определённой выборке; не сравнивать локально видимые объекты с общим числом всей истории.

Точки одного окна и опоры старых событий передаются раздельно: серверное ограничение pivots до 20 не должно ломать линии BOS/SMS или диапазоны.

Оба экрана используют общий отбор/формат слоёв. Ответы разных инструментов, as_of и версий не смешиваются. Поздний ответ после смены актива отбрасывается. Обновления по закрытию H1, подтверждению pivot, lifecycle зоны и смене контекста обновляют зависимые слои без сброса viewport.

Изменения затронут app/web/static/app.js, ltf.js и стили, app/services/overview.py, app/web/ltf_api.py, общие интерфейсы engine/ltf/structure.py, breaks.py, entries.py и при необходимости модели/БД. Выделить общий слой подготовки графика, чтобы исправление одного экрана не оставляло второй с прежней логикой.

Новые инструментальные факты при backfill не рассылать как свежие торговые сигналы. Миграция идемпотентна, с резервной копией и журналом. Настройки визуального лимита не создают новую версию торговой стратегии.

## 8. Приёмочные проверки

| ID | Проверка |
|---|---|
| T01 | 100 доступных основных pivots → ровно последние 20 в хронологическом порядке |
| T02 | Менее 20 → все; 20 считается суммарно по HH/HL/LH/LL |
| T03 | Internal/none/ambiguous/superseded не засоряют стандартный набор |
| T04 | Новая подтверждённая точка вытесняет одну старую; открытая свеча — нет |
| T05 | Скролл/zoom не меняет выбранные 20; история включается явно |
| T06 | Старый pivot вне 20 остаётся опорой BOS/SMS и диапазона |
| T07 | Переход вверх/вниз: есть причинный слом, затем подтверждённая новая пара; время не переносится задним числом |
| T08 | Смена текстовых ролей без подходящего пробоя не создаёт BOS/SMS |
| T09 | Тень, незакрытая H1 и Close==level не дают подтверждённой линии пробоя |
| T10 | BOS/SMS видны без контекста; закрытие/смена сценария не стирает общие события |
| T11 | BOS+SMS на одной свече не дублируют визуально один факт и сохраняют обе записи |
| T12 | Нет старой опоры в viewport — корректное обрезание; неизвестная опора — маркер с объяснением |
| T13 | OB, FVG, BSL и SSL отображаются на обоих экранах; линии нулевой ширины не теряются |
| T14 | Нет сценария → найденные зоны видны с not_evaluated; eligibility не выдумана |

| T16 | Частично заполненная FVG остаётся; завершённая имеет правильный конец; глубокий OB-тест не равен отмене |
| T17 | Скрытая фильтром/внешкальная/ненайденная зона и ошибка API имеют разные объяснения |

| T19 | Быстрая смена BTC/ETH/SOL, context_id и as_of не смешивает ответы |
| T20 | Исторический снимок не содержит будущих ролей, подтверждений и lifecycle |
| T21 | Refresh, resize, переключение H1/HTF и режимов структуры сохраняют корректные слои и настройки |
| T22 | На 360/768/1440 px подписи BOS/SMS читаемы; зоны не закрывают свечи и управление |
| T23 | Повторный replay не дублирует общие события/зоны и не меняет существующий торговый допуск из-за лимита 20 |

Тестировать реальную семантику selector/API/машины и браузерный рендер; проверки наличия слова BOS в исходнике недостаточно. Для приёмки нужны сохранённые снимки до/после на одном as_of и одинаковом viewport. Не задавать обязательное наличие всех четырёх типов на любом рынке: использовать эталоны, где каждый тип действительно обнаружен.

## 9. Готовность результата

Исправление завершено, когда стандартный H1 показывает максимум 20 основных структурных подписей, подтверждённые изменения структуры читаются по BOS/SMS, а найденные OB/FVG/BSL/SSL доступны независимо от торгового сценария. Причина отсутствия каждого слоя объясняется данными или настройкой, а не остаётся незаметной.
